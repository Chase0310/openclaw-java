## 通用规则

### 选项展示规则

- 每层取 **TOP 3** 展示，按优先级排序
- 选项句式固定，`{变量}` 由程序从 reportData 动态填充
- 已点过的选项不再出现
- 按自然日重置（次日 0 点恢复满）

### 说到一半停住（核心规则）

每层 Prompt 输出必须刚好被下一层选项条接住：

| 层级 | 该说 | 不该说（留给下一层） |
|------|------|-------------------|
| L0 推送摘要 | 事实 + 模糊结论 | 不说是哪些知识点（留给 L1） |
| L1 回复 | 具体知识点 + 数据 | 不说怎么练/建议（留给 L2 → E） |
| L2/E 回复 | 具体学习建议 + 推荐应用 | 终点，可以说完 |

### 选项条 sceneId 绑定（核心机制）

每个选项条都必须绑定一个 `sceneId`，点击后**直接跳转到对应场景，不经过路由**。

| sceneId 值 | 含义 | 典型选项 |
|-----------|------|---------|
| A | 学情解读（当前报告详情） | "哪些知识点还需要练？""错题是什么情况？" 等 |
| B | 错因分析 | "为什么错？""为什么会错？" |
| E | 学习规划 | "{知识点}该怎么练？""接下来怎么学？" |
| CLOSE | 收口（系统固定回复） | "好的" |

**分配规则：**
- L1 选项：问当前报告详情 → sceneId = A；"接下来怎么学"类 → sceneId = E
- L2 选项：指向场景E → sceneId = E；指向场景B → sceneId = B；复用L1逻辑 → sceneId = A
- "好的" → sceneId = CLOSE（系统固定回复"收到～有问题随时找我"，不调LLM）

### 选项条点击 vs 自由输入

- **选项条点击** → 按绑定的 sceneId 直接分发到对应场景，不经过路由
- **自由输入** → 走路由判断 → 场景分发

### "好的"收口选项

所有 L2 / 出口选项表的最后一行都包含"好的"选项：

| 好的 | → 收口（系统固定回复） | CLOSE |

- 点击后系统回复固定文案"收到～有问题随时找我"，**不调用LLM**
- 该选项始终存在且始终排在最后一个位置

### 下钻路径结束后（选项栈机制）

选项条采用"先进后出"的栈机制：
- 家长点击一条选项后，该条消失，**同层级剩余选项存起来**
- 当前路径到达E/收口后，**先挂当前层级（L2/B出口）的剩余选项**
- 当前层级全部走完（或家长点"好的"），**弹回上一层级（L1）的剩余选项**
- 所有 L1 全部走完 → 选项消失 → 进入自由输入
- 家长中途自由打字不影响选项栈，当前层级剩余选项保留

### 所有路径终点

**所有下钻路径最终都汇聚到场景 E（学习规划）。**

```
L1 → L2 → E
L1 → L2 → B（错因）→ B出口 → E
L1 → 直达 E（"接下来怎么学"类选项）
```
