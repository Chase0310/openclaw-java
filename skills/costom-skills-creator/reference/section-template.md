# Skill 章节模板

下面是一份适合通用 creator 的最小章节模板，可按场景删减。

```markdown
触发条件：
- 当用户要求查询、整理、判断、承接、分流或继续处理某类结果时使用。

工作流程：
1. 如果上下文中已有关键参数，直接复用，不要重复追问。
2. 调用 `tool_name`，传入 `action=xxx` 与必要参数。
3. 优先读取工具 `output` 中可见的稳定字段，不要依赖运行时内部对象。先看 `status`、`found`、`message`，再看 `record`、`records`、`facts`、`suggestions`、`recommendedNextAction` 与 `handoff`。

参数复用规则：
1. 已在上下文中明确出现的参数直接复用。
2. 只有在关键参数缺失时才补问。
3. 如果返回中已有 `handoff.params`，优先复用它，不要重复追问。

字段说明：
- 按需列出当前工具的关键返回字段。
- 对每个字段写清它是事实字段、建议字段还是承接字段。
- 每个字段至少补齐：类型、作用、字段注释。
- 如果字段是枚举类型，必须列出可选值和每个值的含义。
- 如果字段含义不直观，补一行“何时使用”和“skill 怎么消费”。

返回结果解读规则：
1. 先看 `status` 与 `found`，判断是命中、未命中、待补充还是需要承接下一步。
2. 如果返回中有 `message`，优先用它概括本次工具结果。
3. 如果返回中有 `record`、`records` 或 `facts`，据此提取事实信息。
4. 如果返回中有 `suggestions`、`recommendedNextAction` 或 `handoff`，把它们明确表达为建议或下一步动作。

未命中规则：
1. 如果 `status=not_found` 或 `found=false`，明确说明未找到对应数据。
2. 不要编造不存在的记录、状态、金额、分类或建议。

错误规则：
1. 如果工具执行失败，把返回错误视为参数问题或系统异常。
2. 不要把错误包装成领域结论。

回复规则：
- 用自然语言概括结果。
- 先描述事实字段，再描述建议字段或下一步动作。
- 如果结果中包含 `recommendedNextAction`，把它明确表达为下一步建议。
- 如果结果中包含 `handoff`，先说明为什么切换，再说明会带过去哪些上下文。
```
